## REVIEW ADDENDUM (survey pass, 2026-07-06)

### CONTEXT

- Codebase: `reportifyr` — R package + embedded Python package (`inst/python/reportipyr/`) that assembles Microsoft Word reports from `{rpfy}:file.ext` magic strings, inserting figures/tables/footnotes/alt-text with hash-based provenance tracking; Python is invoked via `uv` subprocess (env owned by external `pyro` R package).
- Primary consumers: internal pharmacometrics/clinical analysts at A2-Ai and GSK producing regulated report deliverables; correctness of what lands in the final docx (right artifact, right footnote, no stale content) matters more than performance.
- Known constraints or intentional decisions worth flagging up front: dual-language design is deliberate (python-docx does what officer cannot); Python dependency pinning lives in the external `pyro` package, not this repo; `.rpfy-logs/` session logs and interactive confirmation prompts are product features. Applied defaults for unanswered maintainer questions are noted `[Q#]` below.
- Areas of specific concern: R↔Python duplicated invariants; the positional-adjacency and hash-in-alt-text machinery (`skip_unchanged`); config sprawl; error propagation across the subprocess boundary.

### REPO MAP

**Purpose.** `reportifyr` generates traceable Microsoft Word reports for pharmacometrics/clinical analysis: analysts save figures/tables through `*_with_metadata()` wrappers that write JSON provenance sidecars (git author, script path, blake3 hash), place `{rpfy}:filename.ext` "magic strings" in a docx shell, and the package inserts formatted artifacts, footnotes, and alt-text into the document, with hash-based skip of unchanged artifacts. Hybrid: an **R package** (user-facing API) wrapping an **embedded Python package** `reportipyr` (docx engine, python-docx) invoked as a subprocess via `uv` (environment owned by the external `pyro` R package).

**Entry points.**
- R exported API (NAMESPACE): orchestrator `build_report()` (`R/build_report.R`); step functions `add_tables()`, `add_plots()`, `add_footnotes()`, `remove_tables_figures_footnotes()`, `finalize_document()`; analysis-time savers `ggsave_with_metadata()`, `write_csv_with_metadata()`, `save_rds_with_metadata()`, `write_object_metadata()`; provenance `rpfy_context()`, `shiny_source()`, `script_source()`; scaffolding `initialize_report_project()`, `sync_report_project()`; validation `validate_docx()`, `validate_config()`, `validate_object()`; logging `toggle_logger()`, `get_log_file()`.
- Python CLI: `inst/python/reportipyr/cli.py`, `uv run -m reportipyr.cli <subcommand>`; 14 subcommands (add-figure, add-figure-alt-text, add-table-alt-text, add-figure-footnotes, add-table-footnotes, remove-footnotes, remove-tables, remove-figures, remove-magic-strings, remove-bookmarks, keep-caption-next, check-alt-text-magic, validate-docx, add-path-overlay, parse-magic-string).
- Load hooks: `R/zzz.R` `.onLoad` (project-root detection from cwd, log pruning, session log setup); `.onAttach` (options status message, uv probing).

**Module inventory.** R ≈ 4,861 lines; Python ≈ 3,194 lines.
- `R/build_report.R` (193) — pipeline orchestrator; sweeps intermediates into `intermediate_files/`.
- `R/add_tables.R` (269) — table insertion **in R** via officer/flextable; own magic regex + raw-XML already-present check.
- `R/add_plots.R` (138), `R/add_footnotes.R` (176), `R/remove_*.R`, `R/keep_caption_next.R`, `R/validate_alt_text_magic_strings.R` — thin wrappers over Python CLI.
- `R/utils.R` (401) — git info, `find_project_root()`, Quarto/this.path source detection, `run_python_script()` (stderr→log callback), `safe_resolve()`.
- `R/rpfy_context.R` (329) + `R/source_meta.R` (305) — S3 provenance classes (shiny/script variants).
- `R/write_object_metadata.R` (106) + saver wrappers — `<name>_<ext>_metadata.json` sidecars, blake3 hash.
- `R/toggle_logger.R` (198) — log4r logger in `.le` env, lazy session log file, pruning.

**Intended layering** (inferred from `build_report.R`, README, `R/reportifyr.R`): user API (R) → validation (R) → docx engine (Python subprocess) — except table insertion, which stays in R. Metadata producer (R, analysis time) ↔ consumer (Python, build time) via JSON sidecar convention and alt-text-embedded hashes.

**Most load-bearing.** (1) `R/utils.R::run_python_script` — every Python call except `R/validate_docx.R`; (2) `inst/python/reportipyr/magic.py` + `alt_text.py` — grammar and hash logic used by every subcommand and partially reimplemented in `R/add_tables.R`; (3) `inst/extdata/config.yaml` keys — read ad hoc at ≥6 R and ~20 Python sites.

**Cross-cutting.** Errors: R `stop()`/log4r; Python `SystemExit(1)`/raise; boundary = exit status + stderr; validate-docx returns JSON on stdout; only footnotes step of `build_report` wrapped in `tryCatch` (`R/build_report.R:146-166`). Config: per-function `yaml::read_yaml`/`config.get`, defaults in three places. Logging: log4r + `.rpfy-logs/` session file (`R/toggle_logger.R`, `R/zzz.R`); Python stderr with `[py]` tag mirrored by callback (`R/utils.R:264-284`), console filtered by `RPFY_VERBOSE`. Validation: `validate_input_args` + `validate_docx` per doc function; `validate_config` only in `add_footnotes`. Concurrency: none (synchronous subprocess pipeline, intermediate docx files on disk). Trust: magic-string paths guarded by twin `safe_resolve`s.

**Build/test/CI.** roxygen2 R package; R deps via `rv` (`rproject.toml`, internal PRISM/pyro repos); Python deps pinned externally by pyro (?) (not verifiable in-repo). CI: `R-CMD-check.yaml` (mac/win/linux, R 4.3–4.5), `python-tests.yaml` (pytest, Python 3.11, **unpinned** python-docx/pillow/pyyaml), `r-release.yml` (binary release). R tests cover pure utilities with mockery stubs at the processx/pyro boundary; Python tests cover docx units; no end-to-end R→Python test in CI.
